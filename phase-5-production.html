    MODULE 17

    Modules, Packages & Imports

    🔑 Core idea

    An import is a find → load → cache pipeline. Every imported module is stored in sys.modules, so its top-level code runs only once per process. Knowing this explains circular imports and what __init__.py is for.

    What import foo does

    import foo → In sys.modules?
    yes → return it     → no → Finders search sys.path → Loader runs the module's code → Cache in sys.modules
    🧠 Memory trick

    “Imported once, shared everywhere.”

    The first import executes the file and caches the module object. Every later import — from any file — just hands back that same object.

    Packages

    mypackage/
├── __init__.py        ← runs on `import mypackage`
├── module_a.py
├── module_b.py
└── subpackage/
    ├── __init__.py
    └── module_c.py
    • __init__.py marks a regular package and runs on first import — often used to re-export names (from .module_a import Thing).
    • Without it you get a namespace package (3.3+) — it works, but explicit is better.
    • __all__ = ["public_func"] controls what from module import * exports. Leading-underscore names are private by convention only.

    Absolute vs relative imports

    # inside mypackage/module_b.py
from mypackage.module_a import helper     # absolute — clear, works everywhere
from .module_a import helper              # relative — only inside a package
from ..other import thing                 # parent package

    Circular imports

    a.py imports b.py, which imports a.py while a is only half-loaded → ImportError or AttributeError.

    # Fix 1: import inside the function that needs it
def process():
    from b import helper
    return helper()

# Fix 2: imports only needed for type hints
from typing import TYPE_CHECKING
if TYPE_CHECKING:
    from b import Helper      # seen by mypy, skipped at runtime

# Fix 3 (best): move the shared code into a third module both can import
    🧠 Memory trick — fixing circles

    “Delay it, hide it, or split it.”

    Delay (function-level import), hide (TYPE_CHECKING), split (restructure).

    ⚠️ Don't forget
    • Top-level code runs on first import — side effects (DB connects, prints) are real.
    • sys.path[0] is the running script's folder (or "" = current directory in the REPL) — a local json.py will shadow the real one.
    • importlib.reload(mod) exists for debugging; don't rely on it in production.
    🤔 Predict the output
    print("loading greet")
def hi(): return "hi"
    import greet
import greet
from greet import hi
print(hi())
    Show answer 
    loading greet
hi

    The module body runs once. The second import and the from … import both reuse the cached object in sys.modules.

    MODULE 18

    Type Hints & Static Analysis

    🔑 Core idea

    Type hints are documentation that tools can check. Python itself ignores them at runtime — a static checker such as mypy or pyright (and your IDE) does the enforcing.

    🧠 Memory trick

    “Hints are for humans and tools — Python doesn't read them.”

    Think guardrails for your editor and CI, not a runtime type system.

    def greet(name: str, times: int = 1) -> str:
    return f"Hello, {name}! " * times

def lengths(items: list[str]) -> dict[str, int]:     # built-in generics (3.9+)
    return {item: len(item) for item in items}

def find_user(user_id: int) -> User | None:          # union syntax (3.10+)
    return db.get(user_id)

    The toolbox

    TypeMeaningExample
    X | None / Optional[X]X or Nonestr | None
    X | Y / Union[X, Y]Either typeint | str
    Literal[...]Only these exact valuesLiteral["r", "w"]
    Type parametersGenericsdef first[T](xs: list[T]) -> T (3.12+)
    ProtocolStructural “duck” typingAnything with .draw()
    TypedDictDict with known keysJSON/API payloads
    @overloadSeveral signaturesReturn type depends on input
    ⚠️ Trap: Optional doesn't mean “optional argument”

    def f(x: Optional[int]) still requires x — it just may be None. An argument is optional only if it has a default.

    Protocol — interfaces without inheritance

    from typing import Protocol

class Drawable(Protocol):
    def draw(self) -> None: ...

class Circle:                       # note: does NOT inherit Drawable
    def draw(self) -> None:
        print("○")

def render(obj: Drawable) -> None:
    obj.draw()

render(Circle())                    # ✅ has draw() → matches
    🧠 Memory trick

    Protocol = “if it quacks”. ABC = “show me your ID”.

    Protocol is structural (matching methods is enough). An ABC is nominal (you must inherit from it).

    Generics

    class Stack[T]:                     # 3.12+ syntax (older: Generic[T] + TypeVar)
    def __init__(self) -> None:
        self._items: list[T] = []
    def push(self, item: T) -> None:
        self._items.append(item)
    def pop(self) -> T:
        return self._items.pop()

s: Stack[int] = Stack()
s.push(42)        # ✅
s.push("hello")   # ❌ mypy: str is not int   (but runs fine at runtime!)
    ⚠️ Don't forget
    • Zero runtime enforcement — wrong types still run until something breaks.
    • Forward references: Python 3.14 evaluates annotations lazily, so def f() -> Node before class Node just works. On older versions use from __future__ import annotations or quote it: "Node".
    • mypy --strict catches more, at the cost of more noise.
    🤔 Predict the output
    def double(x: int) -> int:
    return x * 2

print(double("ab"))
    Show answer 
    abab

    No error at runtime — hints aren't enforced. Only a type checker would flag this call.

    MODULE 19

    Testing with pytest

    🔑 Core idea

    pytest is the standard. Tests follow Arrange → Act → Assert. Fixtures handle setup and teardown; mocks isolate the unit from slow or external dependencies.

    def test_create_user():
    # Arrange
    data = {"name": "Alice", "email": "alice@test.com"}
    # Act
    user = create_user(data)
    # Assert
    assert user.name == "Alice"          # plain assert — pytest shows rich diffs
    🧠 Memory trick

    “Arrange the stage, Act the scene, Assert the review.”

    Fixtures

    import pytest

@pytest.fixture
def db():
    conn = create_connection()    # setup
    yield conn                    # the test runs here
    conn.close()                  # teardown — runs even if the test fails

@pytest.fixture(scope="session")  # created once for the whole run
def big_dataset():
    return load_large_dataset()

def test_query(db):               # injected by matching the parameter name
    assert db.execute("SELECT 1") == 1

    Scopes, narrow to wide: function (default) → class → module → package → session. Put shared fixtures in conftest.py — pytest finds them automatically, no import needed.

    Parametrize

    @pytest.mark.parametrize("text, expected", [
    ("hello", 5),
    ("", 0),
    ("世界", 2),
])
def test_length(text, expected):
    assert len(text) == expected        # 3 separate test cases

def test_rejects_negative():
    with pytest.raises(ValueError, match="must be positive"):
        calculate(-1)

    Mocking

    # myapp/services.py
import requests
def fetch_status(url):
    return requests.get(url).json()["status"]

# tests/test_services.py
from unittest.mock import patch

@patch("myapp.services.requests.get")       # where it's LOOKED UP, not "requests.get"
def test_fetch_status(mock_get):
    mock_get.return_value.json.return_value = {"status": "ok"}
    assert fetch_status("http://api") == "ok"
    mock_get.assert_called_once_with("http://api")
    🧠 Memory trick

    “Patch where it's used, not where it lives.”

    If services.py did from requests import get, you'd patch "myapp.services.get". Patch the name your code actually looks up.

    The test pyramid

              /  E2E  \            ← few, slow, expensive
        / Integration \        ← some
      /   Unit tests    \      ← many, fast, cheap
    ⚠️ Don't forget
    • yield fixtures clean up even when the test fails.
    • pytest's built-in monkeypatch fixture is simpler for env vars and attributes: monkeypatch.setenv("MODE", "test").
    • Too much mocking tests your mocks, not your code — keep some integration tests.
    MODULE 20

    Performance & Profiling

    🔑 Core idea

    Measure first, optimize second. Never guess where the time goes — profile, find the hot path, fix that, then measure again.

    1. Measure→ 2. Identify the hot path→ 3. Optimize→ 4. Verify↺
    🧠 Memory trick

    “Don't guess — measure.”

    Programmers are famously bad at guessing bottlenecks. The profiler is always more honest.

    The tools

    ToolMeasuresUse for
    timeitTime of small snippetsMicro-benchmarks
    cProfileCalls & time per functionFinding slow functions
    line_profiler (pip)Time per lineDrilling into a hot function
    tracemallocMemory allocationsFinding leaks
    py-spy (pip)Sampling, no code changesProfiling live processes
    import timeit
timeit.timeit('"-".join(str(i) for i in range(100))', number=10_000)

# Function-level profile of a whole script, sorted by cumulative time:
#   python -m cProfile -s cumulative script.py

import cProfile, pstats

with cProfile.Profile() as pr:
    main()
pstats.Stats(pr).sort_stats("cumulative").print_stats(20)   # top 20

    Optimization patterns

    Anti-patternFixGain
    s += piece in a loop"".join(pieces)O(n²) → O(n)
    x in big_list repeatedlyx in big_setO(n) → O(1)
    Recomputing the same result@lru_cacheDepends on reuse
    list.insert(0, x)collections.dequeO(n) → O(1)
    Millions of small objects__slots__Less memory, less GC
    Pure-Python number loopsNumPy / vectorizeOften 10–100×
    🧠 Memory trick — the optimization ladder

    Algorithm → Data structure → Python idiom → C extension.

    Climb in that order. A better algorithm beats any micro-trick; only reach for NumPy/Cython/Rust once the top rungs are done.

    ⚠️ Don't forget
    • timeit turns off the GC while timing — real code may be slower.
    • cProfile adds overhead to every call, which distorts very fast functions — use timeit for those.
    • Comprehensions usually beat map + lambda; f-strings beat % and .format().
    • Caching a global like len in a local helped a lot before 3.11; the modern interpreter caches global lookups, so the gain is small now.

    ⚠️ Gotchas checklist

    Skim this the night before an interview.

    1. sys.modules caches modules — a second import doesn't re-run the code.
    2. Top-level module code runs on first import — side effects are real.
    3. A local file named like a stdlib module (json.py, random.py) shadows it.
    4. Type hints are not enforced at runtime.
    5. Optional[X] means “X or None”, not “optional argument”.
    6. Mock where it's imported, not where it's defined.
    7. conftest.py fixtures are auto-discovered.
    8. timeit disables the GC while timing.
    9. cProfile overhead distorts tiny functions — use timeit.
    10. Optimize the algorithm before micro-tuning.
