    MODULE 14

    Threading

    🔑 Core idea

    Threads give you concurrency for I/O-bound work. The GIL is released while a thread waits on the network or disk, so other threads keep going. For pure-Python CPU work, threads don't help.

    The modern API: ThreadPoolExecutor

    from concurrent.futures import ThreadPoolExecutor, as_completed
import urllib.request

def fetch(url):
    with urllib.request.urlopen(url, timeout=10) as resp:
        return resp.status

urls = ["https://python.org", "https://pypi.org", "https://docs.python.org"]

with ThreadPoolExecutor(max_workers=10) as pool:
    # Option 1: map — results in INPUT order
    statuses = list(pool.map(fetch, urls))

    # Option 2: submit + as_completed — results in COMPLETION order
    futures = {pool.submit(fetch, u): u for u in urls}
    for fut in as_completed(futures):
        print(futures[fut], fut.result())
    🧠 Memory trick

    map = “in the order I asked”. as_completed = “whoever finishes first”.

    Synchronization primitives

    PrimitivePurposeTypical use
    LockOnly one thread at a timeProtect counter += 1
    RLockSame thread can re-acquireRecursive code paths
    Semaphore(n)At most n threads at a timeConnection limits
    EventOne-time signal“Please shut down” flag
    ConditionWait until notifiedProducer–consumer
    queue.QueueThread-safe hand-offThe easiest producer–consumer
    import threading

balance = 0
lock = threading.Lock()

def deposit(amount):
    global balance
    with lock:                   # acquire … release, even on exceptions
        balance += amount
    ⚠️ Don't forget
    • Race condition = two threads read-modify-write the same data without a lock.
    • Daemon threads are killed abruptly when the main thread exits — no cleanup.
    • Each thread reserves its own stack (8 MB by default on Linux) — thousands of threads get expensive.
    • Prefer ThreadPoolExecutor over managing threading.Thread objects by hand.
    🤔 Predict the output
    from concurrent.futures import ThreadPoolExecutor
import time

def slow_square(n):
    time.sleep(1 - n * 0.3)      # bigger n finishes sooner
    return n * n

with ThreadPoolExecutor() as pool:
    print(list(pool.map(slow_square, [1, 2, 3])))
    Show answer 
    [1, 4, 9]

    map always returns results in input order, even though 3 finished first. Total time ≈ 0.7 s, not 1.8 s — the sleeps overlap.

    MODULE 15

    Multiprocessing

    🔑 Core idea

    Multiprocessing gets true CPU parallelism by running separate processes — each with its own interpreter, memory and GIL. Use it for CPU-bound work: number crunching, image processing, parsing.

    The modern API: ProcessPoolExecutor

    from concurrent.futures import ProcessPoolExecutor

def heavy_compute(n):                 # must be a top-level function (picklable)
    return sum(i * i for i in range(n))

if __name__ == "__main__":            # MANDATORY with spawn / forkserver
    with ProcessPoolExecutor() as pool:          # defaults to one worker per CPU
        results = list(pool.map(heavy_compute, [10**6] * 4))
    print(sum(results))
    🧠 Memory trick — the main guard

    “Children re-read the script — guard the front door.”

    A spawned child imports your file again. Without if __name__ == "__main__": it would start its own pool, whose children start pools… an accidental process explosion.

    Start methods: fork vs spawn vs forkserver

    forkspawnforkserver
    HowCopy the parent processStart a fresh interpreterFork from a clean helper process
    SpeedFastest (copy-on-write)SlowestIn between
    Safe with threads?❌ Copies held locks → deadlocks✅✅
    Default onLinux ≤ 3.13Windows, macOSLinux 3.14+
    import multiprocessing as mp

if __name__ == "__main__":
    mp.set_start_method("spawn")     # call ONCE, inside the guard
    ...

    Sharing data between processes (IPC)

    MechanismUse caseSpeed
    QueueProducer–consumerMedium
    PipeTwo-process channelFast
    Value / Array / shared_memoryRaw shared memoryFastest
    ManagerShared Python objects via proxiesSlowest
    🧠 Memory trick

    “Everything crossing the border gets pickled.”

    Arguments and results are serialized with pickle. Lambdas, nested functions and open files can't be pickled — and pickling big data can cost more than the work itself.

    ⚠️ Don't forget
    • Each process costs tens of MB — don't spawn thousands.
    • For tiny tasks, serialization overhead can wipe out the speed-up. Batch work into bigger chunks.
    • Never fork a process that already runs threads.
    🤔 Predict the output
    from concurrent.futures import ProcessPoolExecutor

if __name__ == "__main__":
    with ProcessPoolExecutor() as pool:
        print(list(pool.map(lambda x: x * 2, [1, 2, 3])))
    Show answer 
    PicklingError: Can't pickle <function <lambda> ...>

    The function itself must be sent to the worker process, and lambdas can't be pickled. Define a normal top-level def double(x) instead.

    MODULE 16

    Asyncio

    🔑 Core idea

    Asyncio is cooperative concurrency on a single thread. An event loop runs coroutines, and each one voluntarily hands control back at every await. Ideal for thousands of simultaneous network connections — a coroutine costs about a kilobyte, a thread megabytes.

    🧠 Memory trick — one waiter, a thousand tables

    While table 7 is reading the menu (waiting on I/O), the waiter serves table 12. But if the waiter goes into the kitchen to cook (CPU work or a blocking call), every table waits.

    The basics

    import asyncio, time

async def work(name, delay):          # `async def` → calling it returns a coroutine
    await asyncio.sleep(delay)        # suspension point: the loop runs others meanwhile
    return name

async def main():
    start = time.perf_counter()
    results = await asyncio.gather(work("slow", 2), work("fast", 1))
    print(results, round(time.perf_counter() - start, 1))

asyncio.run(main())                   # ['slow', 'fast'] 2.0  ← concurrent, input order

    Key APIs

    APIWhat it does
    asyncio.run(main())Entry point — creates and runs the event loop
    await xSuspend until x finishes
    asyncio.gather(*coros)Run concurrently; results in input order
    asyncio.TaskGroup() (3.11+)Structured concurrency — cancels siblings if one fails
    asyncio.create_task(coro)Schedule in the background
    asyncio.timeout(s) (3.11+)Cancel the block if it takes too long
    asyncio.to_thread(func)Run blocking code in a thread without freezing the loop
    asyncio.Semaphore(n)Limit how many run at once
    async def main():
    async with asyncio.TaskGroup() as tg:          # modern alternative to gather
        t1 = tg.create_task(work("a", 1))
        t2 = tg.create_task(work("b", 1))
    print(t1.result(), t2.result())                # a b   (after ~1 s total)

    try:
        async with asyncio.timeout(0.5):
            await work("x", 2)
    except TimeoutError:
        print("timed out")

    Real-world pattern: rate-limited HTTP

    import asyncio
import aiohttp

async def fetch(session, sem, url):
    async with sem:                               # at most 50 in flight
        async with session.get(url) as resp:
            return await resp.json()

async def main(urls):
    sem = asyncio.Semaphore(50)
    async with aiohttp.ClientSession() as session:
        return await asyncio.gather(*(fetch(session, sem, u) for u in urls))
    ⚠️ Don't forget
    • A blocking call freezes the whole loop — time.sleep(), requests.get(), heavy CPU. Use await asyncio.sleep(), async libraries (aiohttp, asyncpg) or asyncio.to_thread().
    • Calling a coroutine function does nothing until it's awaited or made a task.
    • You can't await inside a regular def.
    • No locks needed between await points — nothing can interrupt you there.
    🧠 Memory trick

    “No await, no break.”

    Other coroutines only get a turn when the current one hits an await. Code without awaits hogs the loop.

    🤔 Predict the output
    import asyncio, time

async def bad(name):
    time.sleep(1)                     # blocking!
    return name

async def main():
    start = time.perf_counter()
    await asyncio.gather(bad("a"), bad("b"))
    print(round(time.perf_counter() - start, 1))

asyncio.run(main())
    Show answer 
    2.0

    time.sleep never yields to the loop, so the two “concurrent” coroutines run back to back. Swap in await asyncio.sleep(1) and it prints 1.0.

    🧭 Which one do I use?

    Your situationReach for
    I/O-bound, under ~100 concurrent operations, sync librariesThreads — ThreadPoolExecutor
    I/O-bound, hundreds to tens of thousands of connectionsAsyncio
    CPU-bound (math, images, parsing)Processes — ProcessPoolExecutor
    Both I/O and CPUAsyncio + loop.run_in_executor(ProcessPoolExecutor())

    ⚠️ Gotchas checklist

    Skim this the night before an interview.

    1. counter += 1 is not atomic — lock shared state.
    2. Daemon threads are killed on exit — no cleanup.
    3. Each thread reserves MBs of stack — thousands get expensive.
    4. fork + threads = deadlocks.
    5. Everything sent to a process must be picklable — no lambdas.
    6. The __main__ guard is mandatory with spawn/forkserver.
    7. A blocking call in async code freezes the event loop — use to_thread().
    8. asyncio.gather() keeps input order.
    9. Coroutines do nothing until awaited or scheduled as tasks.
    10. Asyncio needs no locks between await points.
