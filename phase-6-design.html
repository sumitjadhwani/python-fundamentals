    MODULE 21

    Design Patterns in Python

    🔑 Core idea

    Python needs fewer classic design patterns than Java or C++. First-class functions, duck typing, modules and generators replace much of the ceremony. If a pattern needs five classes, there's usually a one-function Python version.

    PatternJava wayPython way
    StrategyInterface + classesPass a function
    ObserverListener interfaceList of callbacks
    SingletonPrivate constructorA module-level object
    FactoryFactory classA function, or a registry dict
    IteratorIterator classGenerator function
    Decorator / ProxyWrapper class@decorator
    Template methodAbstract base classFunction with a callback argument
    Builder / DTOBuilder class@dataclass
    🧠 Memory trick — the four swaps

    Functions replace classes · Modules replace singletons · Generators replace iterators · with replaces try/finally.

    Singleton — use the module

    class Settings:
    def __init__(self):
        self.debug = False
        self.db_url = "postgres://localhost/app"

settings = Settings()        # created once, on first import
    from config import settings  # every importer gets the SAME object (sys.modules cache)
    # If you truly need a class-level singleton:
class Singleton:
    _instance = None
    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

Singleton() is Singleton()   # True
    🧠 Memory trick

    “A module is a singleton.”

    It's executed once and cached in sys.modules (Phase 5) — no tricks needed.

    Strategy — just pass a function

    def process(data, transform):
    return [transform(item) for item in data]

names = ["ada", "guido", "grace"]
process(names, str.upper)            # ['ADA', 'GUIDO', 'GRACE']
process(names, lambda s: s[:2])      # ['ad', 'gu', 'gr']
sorted(names, key=len)               # the stdlib does this everywhere: key=, default=…

    Registry / plugins with __init_subclass__

    class Handler:
    registry = {}

    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        Handler.registry[cls.__name__.lower()] = cls   # runs when a subclass is DEFINED

class JsonHandler(Handler): pass
class XmlHandler(Handler): pass

Handler.registry
# {'jsonhandler': JsonHandler, 'xmlhandler': XmlHandler}  ← auto-registered

def make_handler(kind):              # factory = a dict lookup
    return Handler.registry[kind]()

    Resource management — a context manager

    from contextlib import contextmanager

@contextmanager
def managed_connection(url):
    conn = create_connection(url)
    try:
        yield conn
    finally:
        conn.close()                 # guaranteed, even on exceptions

with managed_connection("postgres://...") as conn:
    conn.execute("SELECT 1")

    Data containers — @dataclass

    from dataclasses import dataclass, field

@dataclass
class Config:
    host: str
    port: int = 8080
    tags: list[str] = field(default_factory=list)   # never `= []` (Phase 1 trap!)

    def __post_init__(self):                         # validation hook
        if not 0 < self.port < 65536:
            raise ValueError("port out of range")

Config("localhost")   # Config(host='localhost', port=8080, tags=[])
    ⚠️ Don't forget
    • Don't over-engineer — porting Java patterns 1:1 makes Python code worse.
    • __init_subclass__ (3.6+) is the simple way to build plugin registries; no metaclass needed.
    • Mutable dataclass defaults need field(default_factory=...) — @dataclass raises an error if you write = [].
    🤔 Predict the output
    class Plugin:
    names = []
    def __init_subclass__(cls, **kw):
        super().__init_subclass__(**kw)
        Plugin.names.append(cls.__name__)

class A(Plugin): pass
class B(A): pass

print(Plugin.names)
    Show answer 
    ['A', 'B']

    The hook fires for every subclass at any depth — B inherits from A, which inherits from Plugin — and it fires at class definition time, without creating instances.

    MODULE 22

    Python in System Design

    🔑 Core idea

    Python web services scale with processes, not threads: an app server runs several worker processes (each with its own GIL), slow work goes to a task queue, and connections are pooled. Know the stack and be honest about Python's limits.

    The typical Python web stack

    Client→ Load balancer
    Nginx / ALB    → App server
    Gunicorn / Uvicorn    → Your app
    Django / Flask / FastAPI    → Redis · PostgreSQL · Celery

    WSGI vs ASGI

    WSGIASGI
    ModelSynchronousAsync-native
    FrameworksFlask, Django (classic)FastAPI, Starlette, Django (async views)
    ServerGunicornUvicorn, Hypercorn
    WebSockets / streaming❌✅
    Best forClassic REST and CRUDWebSockets, streaming, high-concurrency I/O
    🧠 Memory trick

    The “A” in ASGI is for Async.

    Gunicorn workers

    Worker classModelUse when
    syncOne request at a time per processSimple or CPU-heavy APIs
    gthreadThread pool inside each processI/O-heavy app on a sync framework
    uvicorn.workers.UvicornWorkerEvent loop per processFastAPI / ASGI apps
    gunicorn app:app --workers 4 --worker-class uvicorn.workers.UvicornWorker --bind 0.0.0.0:8000
# classic starting point: workers = (2 × CPU cores) + 1
    🧠 Memory trick

    “Workers are processes — each brings its own GIL.”

    That's how a Python web app uses every core: parallelism lives at the process level, so the GIL stops mattering.

    Background jobs with Celery

    Web API
    task.delay()    → Broker
    Redis / RabbitMQ    → Workers 1…N→ Result backend
    optional     
    from celery import Celery

app = Celery("tasks", broker="redis://localhost:6379/0")

@app.task(bind=True, max_retries=3, default_retry_delay=60)
def process_order(self, order_id):        # pass IDs, not objects
    try:
        return charge_and_ship(order_id)
    except TransientError as exc:
        raise self.retry(exc=exc)

process_order.delay(42)                   # returns immediately; a worker runs it
    🧠 Memory trick — Celery's golden rules

    “Idempotent, serializable, time-boxed.”

    • Idempotent — retries will happen; running twice must be safe.
    • Serializable — JSON-friendly args (IDs, not ORM objects).
    • Time-boxed — set task_time_limit so stuck workers die; task_acks_late=True for at-least-once delivery.

    Connection pooling

    from sqlalchemy import create_engine

engine = create_engine(
    "postgresql://user:pass@db/app",
    pool_size=20,          # keep 20 connections open
    max_overflow=10,       # allow 10 extra under load
    pool_pre_ping=True,    # check a connection is alive before using it
    pool_recycle=3600,     # replace connections after an hour
)

    Opening a database connection can take tens of milliseconds (TCP, TLS, auth). A pool pays that once and reuses connections — mandatory in production for DBs, Redis and HTTP clients.

    An async endpoint (FastAPI)

    from fastapi import FastAPI, BackgroundTasks

app = FastAPI()

@app.get("/users/{user_id}")
async def get_user(user_id: int):          # path param is validated as int
    return {"user": await db.fetch_user(user_id)}

@app.post("/orders")
async def create_order(order: OrderIn, bg: BackgroundTasks):
    order_id = await db.insert_order(order)
    bg.add_task(send_confirmation_email, order.email)   # runs after the response
    return {"order_id": order_id}

    Is Python the right tool?

    ✅ Python wins

    • Rapid prototyping and product iteration
    • Data, ML and AI pipelines (NumPy, pandas, PyTorch)
    • Automation, scripting and glue code
    • Web APIs at moderate scale

    ⚠️ Consider something else

    • Sub-millisecond latency → Go, Rust, C++
    • Heavy CPU work without C extensions → Rust, Go
    • Mobile / embedded → Swift, Kotlin, C
    • Browser front-end → TypeScript

    Quick decision guide

    Building…Typical choice
    Classic REST / CRUD appDjango or Flask + Gunicorn (sync workers)
    WebSockets, streaming, high-concurrency I/OFastAPI + Uvicorn
    Background jobsCelery + Redis / RabbitMQ
    Scheduled data pipelinesAirflow, Prefect, Dagster
    ML model servingFastAPI (async) or a dedicated model server
    ⚠️ Don't forget
    • A sync worker is blocked for the whole request — size the worker count to the traffic.
    • Never call blocking libraries inside async def endpoints (Phase 4) — use async drivers or a plain def endpoint, which FastAPI runs in a thread pool.
    • Python's edge is ecosystem and development speed, not raw performance.

    ⚠️ Gotchas checklist

    1. Gunicorn workers are processes, not threads — each has its own GIL.
    2. Worker formula: (2 × CPU cores) + 1 as a starting point.
    3. Celery tasks must be idempotent — retries happen.
    4. Celery args must be serializable — pass IDs, not objects.
    5. Connection pooling is mandatory in production.
    6. A module-level instance is the Pythonic singleton.
    7. __init_subclass__ for plugin registries.
    8. First-class functions remove the need for many classic patterns.
    9. FastAPI + Uvicorn for async; Django/Flask + Gunicorn for sync.
    10. Python's strength is ecosystem and speed of development, not raw speed.

    🏁 All-phases final sheet

    The 20 traps that come up most often, across the whole course.

    1. is for values → wrong. Only for None, True, False.
    2. The small-int cache is a CPython detail — never rely on it.
    3. def f(x=[]) → shared across calls; use a None sentinel.
    4. += on a list mutates in place; on a tuple it creates a new object.
    5. del deletes the name, not the object.
    6. Pass-by-object-reference: mutations travel, rebinds stay home.
    7. list.pop(0) is O(n) → deque.
    8. defaultdict inserts on read.
    9. String += in a loop is O(n²) → join().
    10. len(str) counts characters, len(bytes) counts bytes.
    11. Generators are single-use.
    12. Late-binding closures → lambda i=i: i.
    13. @functools.wraps is non-negotiable in decorators.
    14. super() follows the MRO, not the parent.
    15. Bare except: swallows Ctrl+C.
    16. lru_cache needs hashable arguments.
    17. counter += 1 is not thread-safe.
    18. The GIL protects CPython internals, not your code.
    19. fork + threads = deadlocks.
    20. Mock where it's imported, not where it's defined.
