    MODULE 1

    Everything is an Object

    💬 In plain English

    Every value in Python — a number, a piece of text, a list, even a function — is an object: a thing that lives in memory. Each object has three things: an id (where it lives), a type (what kind of thing it is) and a value (what's inside).

    age = 25

print(type(age))   # → <class 'int'>      what kind of thing
print(id(age))     # → 140713...           where it lives (your number will differ)
print(age)         # → 25                  what's inside

    Same value or the same object? == vs is

    👯
    Think of identical twins.

    They look exactly the same (== is True), but they're two different people (is is False).

    a = [1, 2, 3]
b = [1, 2, 3]
c = a

print(a == b)   # → True    same contents
print(a is b)   # → False   two separate lists that happen to match
print(a is c)   # → True    c is just another name for the same list
    🧠 Memory trick

    == asks “do they look the same?” · is asks “is it literally the same thing?”

    In everyday code, use ==. Use is only to check for None: if result is None:

    Can it change? Mutable vs immutable

    📝
    Whiteboard vs printed page.

    Some objects are like a whiteboard — you can erase and change them (mutable). Others are like a printed page — to “change” one, you have to print a new page (immutable).

    📝 Mutable (whiteboard)

    listdictset

    📄 Immutable (printed page)

    intfloatboolstrtupleNone
    nums = [1, 2, 3]
nums.append(4)          # the list itself changes
print(nums)             # → [1, 2, 3, 4]

name = "sam"
name.upper()            # makes a NEW string; the original is untouched
print(name)             # → sam
name = name.upper()     # point the name at the new string
print(name)             # → SAM
    🧠 Memory trick

    “Containers you can add to are mutable. Simple values are not.”

    If it has .append(), .add() or [key] = …, it's a whiteboard.

    Why it matters: dictionary keys

    A dictionary needs its keys to never change, otherwise it couldn't find them again. So only immutable things can be keys.

    cities = {(19.07, 72.87): "Mumbai"}    # ✅ a tuple can be a key
cities = {[19.07, 72.87]: "Mumbai"}    # ❌ TypeError: unhashable type: 'list'
    🤔 Predict the output
    x = "hello"
y = x
x = x + "!"
print(y)
    Show answer 
    hello

    Strings can't change. x + "!" builds a brand-new string and only x moves to it. y still points at the original "hello".

    ✅ Remember
    • Every value is an object with an id, a type and a value.
    • == compares values; is checks it's the same object — use it only for None.
    • Lists, dicts and sets can change; numbers, strings and tuples can't.
    🔬 Go deeper — interview details, optional

    Identity, type and value never “drift”

    PropertyCan it change?Inspect with
    IdentityNeverid(x) (memory address in CPython)
    TypeNevertype(x)
    ValueOnly if mutableprint(x)

    Small integer cache

    CPython pre-creates the integers -5 to 256, so a is b can be True for small numbers and False for big ones. It's an implementation detail — another reason never to use is for numbers.

    “Hashable” is the real rule for dict keys

    Keys must be hashable: Python turns them into a number (hash(x)) to find them fast. Immutable built-ins are hashable. A tuple is hashable only if everything inside it is — hash((1, [2])) raises TypeError because of the list inside.

    Fun facts

    • type(type) → <class 'type'>: type is an instance of itself.
    • None is a singleton — there is exactly one in the whole program.
    • Immutable ≠ constant: you can point a name at a new object; you can't change the object.
    MODULE 2

    Variables Are Name Tags

    💬 In plain English

    A variable is a name tag, not a box. x = 5 ties the tag x to the object 5. Writing y = x ties a second tag to the same object — nothing gets copied.

    🔗
    Sharing a Google Doc.

    b = a is like sending someone the link: you both edit the same document. To give them their own version, you have to make a copy.

    shopping = ["milk", "eggs"]
my_list = shopping              # same list, two names
my_list.append("bread")

print(shopping)                 # → ['milk', 'eggs', 'bread']   ← surprise!

    Making a real copy

    shopping = ["milk", "eggs"]
my_list = shopping.copy()       # also works: list(shopping) or shopping[:]
my_list.append("bread")

print(shopping)                 # → ['milk', 'eggs']   unchanged ✅
print(my_list)                  # → ['milk', 'eggs', 'bread']

    Copies of nested data: shallow vs deep

    .copy() only copies the outer container. Anything nested inside is still shared.

    📁
    Folders and papers.

    A shallow copy is a new folder holding the same papers. A deep copy is a new folder with photocopies of every paper.

    import copy

team = {"name": "Blue", "members": ["Asha", "Ravi"]}

shallow = team.copy()
shallow["members"].append("Neha")
print(team["members"])          # → ['Asha', 'Ravi', 'Neha']   inner list was shared!

deep = copy.deepcopy(team)
deep["members"].append("Zoe")
print(team["members"])          # → ['Asha', 'Ravi', 'Neha']   fully independent ✅

    Passing things into functions

    A function receives a new name tag on your object. If it changes the object, you see the change. If it just points its tag somewhere else, you don't.

    def add_item(cart):
    cart.append("pen")          # changes the shared list

def reset(cart):
    cart = []                   # only moves the function's own tag

my_cart = ["book"]
add_item(my_cart)
print(my_cart)                  # → ['book', 'pen']
reset(my_cart)
print(my_cart)                  # → ['book', 'pen']   reset had no effect
    🧠 Memory trick

    “Changes travel, reassignments stay home.”

    🤔 Predict the output
    a = [1, 2]
b = a
a = a + [3]     # note: not .append()
print(b)
    Show answer 
    [1, 2]

    a + [3] builds a new list and moves only the tag a. b still points at the old one. (With a.append(3) or a += [3], both would see [1, 2, 3].)

    ✅ Remember
    • = never copies — it attaches a name to an object.
    • Need an independent list or dict? .copy(). Nested data? copy.deepcopy().
    • Functions can change your mutable objects, but can't reassign your variables.
    🔬 Go deeper — memory and reference counting

    Reference counting

    CPython counts how many names and containers point at each object. When the count drops to zero, the object is freed immediately.

    import sys
x = [1, 2, 3]
sys.getrefcount(x)   # → 2   (x, plus a temporary reference for the call itself)
y = x                # count goes up
del y                # del removes the NAME; the object lives while others point at it

    “Pass by object reference”

    The official name for the function behaviour above. Python is neither “pass by value” (it doesn't copy) nor “pass by reference” (the function can't reassign your variable).

    += behaves differently by type

    On a list, a += [3] changes the list in place (everyone sharing it sees it). On a string or tuple, += builds a new object and moves the name.

    What CPython reuses

    Small ints (-5…256), short identifier-like strings, and None/True/False are created once and reused.

    MODULE 3

    Lists, Tuples, Dicts & Sets

    💬 In plain English

    Python has four built-in containers. Each is good at one job — pick the one that matches what you need to do with the data.

    ContainerReal-life versionGood atLooks like
    list📝 To-do listKeeping things in order, adding more["milk", "eggs"]
    tuple📍 GPS coordinatesA fixed group that won't change(19.07, 72.87)
    dict📒 Phone bookLooking something up by a key{"Asha": 9876}
    set🎟️ Guest listUnique items, fast “is X here?”{"Asha", "Ravi"}
    todo = ["email", "gym"]
todo.append("groceries")              # list: ordered, grows
print(todo[0])                        # → email

point = (3, 4)
x, y = point                          # tuple: fixed; unpack into names

phone = {"Asha": 9876, "Ravi": 5432}
print(phone["Asha"])                  # → 9876        dict: look up by key
phone["Neha"] = 1111                  # add or update

guests = {"Asha", "Ravi", "Asha"}
print(guests)                         # → {'Asha', 'Ravi'}   set: duplicates vanish
print("Ravi" in guests)               # → True

    Speed, in plain words

    • Dict and set lookups are instant — even with a million items, key in d takes the same time.
    • Searching a list checks items one by one — x in my_list gets slower as the list grows.
    • Adding/removing at the end of a list is fast; at the front it's slow (everything shifts).
    🧠 Memory trick — choose by the question you ask
    • “Is X in here?” → set
    • “What's the value for X?” → dict
    • “What's next, in order?” → list
    • “A fixed record?” → tuple

    Three handy helpers from collections

    from collections import Counter, defaultdict, deque

# Counter — count things in one line
votes = ["tea", "coffee", "tea", "tea"]
print(Counter(votes).most_common(1))  # → [('tea', 3)]

# defaultdict — no "if key not in dict" boilerplate
by_letter = defaultdict(list)
for name in ["Asha", "Amit", "Ravi"]:
    by_letter[name[0]].append(name)
print(dict(by_letter))                # → {'A': ['Asha', 'Amit'], 'R': ['Ravi']}

# deque — a queue that's fast at BOTH ends
line = deque(["Asha", "Ravi"])
line.append("Neha")                   # join at the back
print(line.popleft())                 # → Asha   served from the front
    ⚠️ Common mistake: changing a dict while looping over it
    stock = {"apple": 0, "pear": 3}
for item in stock:
    if stock[item] == 0:
        del stock[item]        # ❌ RuntimeError: dictionary changed size during iteration

for item in list(stock):       # ✅ loop over a snapshot of the keys
    if stock[item] == 0:
        del stock[item]
    🤔 Predict the output
    emails = ["a@x.com", "b@x.com", "a@x.com"]
print(len(set(emails)))
    Show answer 
    2

    Turning a list into a set is the quickest way to remove duplicates (but you lose the order).

    ✅ Remember
    • list = ordered, tuple = fixed, dict = key → value, set = unique.
    • Checking membership a lot? Use a set or dict, not a list.
    • Don't add or delete keys while looping over a dict — loop over list(d).
    🔬 Go deeper — Big-O and internals

    list = dynamic array

    OperationTime
    lst[i], append, pop()O(1)
    insert(0, x), pop(0), x in lstO(n)

    dict / set = hash tables

    Average O(1) lookups and inserts; the table resizes when about ⅔ full. Dicts keep insertion order (guaranteed since Python 3.7) — not sorted order.

    list : [ptr0|ptr1|ptr2|...|spare|spare]   ← extra room to grow
tuple: [ptr0|ptr1|ptr2]                   ← exact size
dict : sparse index → dense entries (insertion order)

    Gotchas

    • defaultdict inserts a key just by reading it: d["missing"] creates it. Use d.get(key) to peek.
    • Set operators: a | b union, a & b intersection, a - b difference.
    • A class that defines __eq__ but not __hash__ can't be put in a set (Phase 2, M8).
    MODULE 4

    Strings, Text & Bytes

    💬 In plain English

    A str is text — characters you can read. Computers store and send text as bytes (raw numbers), using an encoding to translate between the two. UTF-8 is the standard encoding almost everywhere.

    text = "café"
data = text.encode("utf-8")      # text → bytes  (to save or send)
print(data)                      # → b'caf\xc3\xa9'
print(data.decode("utf-8"))      # → café        bytes → text  (after reading)

print(len("café"))               # → 4   characters
print(len(data))                 # → 5   bytes — é takes 2 bytes in UTF-8
    🧠 Memory trick — the Unicode sandwich

    Bytes on the outside, text in the middle.

    Decode when data comes in (file, network) → work with str → encode when it goes out.

    f-strings: the easy way to build text

    name, score, price = "Asha", 0.92, 1499

print(f"Hi {name}!")              # → Hi Asha!
print(f"Score: {score:.0%}")      # → Score: 92%
print(f"Price: ₹{price:,}")       # → Price: ₹1,499
print(f"{3.14159:.2f}")           # → 3.14
print(f"{name=}")                 # → name='Asha'   handy for debugging
    ⚠️ Common mistake: gluing text to a number
    age = 25
print("Age: " + age)          # ❌ TypeError: can only concatenate str (not "int") to str
print("Age: " + str(age))     # ✅
print(f"Age: {age}")          # ✅ cleaner

    Joining many pieces

    words = ["Python", "is", "fun"]

sentence = " ".join(words)       # ✅ fast, one step
print(sentence)                  # → Python is fun

# Avoid building big strings with += in a loop — each step makes a whole new string.

    Reading files

    with open("notes.txt", encoding="utf-8") as f:   # always say the encoding
    content = f.read()

    Without encoding="utf-8", Python uses your operating system's default — on Windows that can garble non-English text.

    🤔 Predict the output
    word = "naïve"
print(len(word), len(word.encode("utf-8")))
    Show answer 
    5 6

    5 characters, but 6 bytes — the ï needs two bytes in UTF-8.

    ✅ Remember
    • str = text, bytes = raw data. Convert with .encode() / .decode().
    • Use f-strings to mix text and values.
    • Use "".join(...) for many pieces, and encoding="utf-8" when opening files.
    🔬 Go deeper — UTF-8 sizes and performance

    UTF-8 is variable-width

    CharactersBytes eachExample
    Basic English (ASCII)1A
    Accented Latin, Greek…2é
    Most other scripts (हिन्दी, 世界)3世
    Emoji and rare symbols4🐍

    Why += in a loop is slow

    Strings are immutable, so each s += piece copies everything so far into a new string. For n pieces that's roughly n² work. "".join(pieces) does it in one pass.

    How CPython stores strings (PEP 393)

    Each string uses 1, 2 or 4 bytes per character — the smallest size that fits its widest character. One emoji in a long English string makes the whole string use 4 bytes per character in memory.

    You can't mix the two

    "a" + b"b" raises TypeError. Python never guesses an encoding for you.

    MODULE 5

    Functions & Scope

    💬 In plain English

    A function is a reusable recipe. In Python a function is also an ordinary object, so you can store it in a variable or hand it to another function. Scope is the set of rules for where Python looks up a name.

    def shout(text):
    return text.upper() + "!"

yell = shout                       # functions are objects — give it another name
print(yell("hi"))                  # → HI!

names = ["ravi", "Asha", "neha"]
print(sorted(names, key=str.lower))   # → ['Asha', 'neha', 'ravi']   pass a function in

    Where does Python look for a name? (LEGB)

    Python searches from the innermost box outwards and uses the first match.

    B · Built-in — print, len, range
    G · Global — names at the top of your file
    E · Enclosing — the outer function, if nested
    L · Local — names created inside this function (checked first)
    🧠 Memory trick

    “Look locally first, then go bigger.” — Local → Enclosing → Global → Built-in

    greeting = "Hello"            # global

def welcome(name):
    message = f"{greeting}, {name}"   # message is local; greeting is found globally
    return message

print(welcome("Asha"))        # → Hello, Asha
print(message)                # ❌ NameError — local names don't exist outside
    ⚠️ Common mistake: changing a global inside a function
    score = 0

def add_point():
    score += 1                 # ❌ UnboundLocalError

# ✅ Best fix: pass the value in and return the new one
def add_point(score):
    return score + 1

score = add_point(score)

    Assigning to a name anywhere in a function makes it local for the whole function, so Python never looks at the global score.

    Default arguments — and their famous trap

    def greet(name, greeting="Hello"):     # greeting is optional
    return f"{greeting}, {name}"

greet("Asha")                # → Hello, Asha
greet("Asha", "Hi")          # → Hi, Asha
    ⚠️ Never use a list (or dict) as a default
    def add_task(task, tasks=[]):        # ❌ the SAME list is reused every call
    tasks.append(task)
    return tasks

add_task("email")                    # → ['email']
add_task("gym")                      # → ['email', 'gym']   ← leaked from last call!

def add_task(task, tasks=None):      # ✅ use None, create the list inside
    if tasks is None:
        tasks = []
    tasks.append(task)
    return tasks

    The default value is created once, when Python reads the def — not each time you call it.

    🧠 Memory trick

    “Defaults are baked once.” Mutable default? Use None.

    Flexible arguments

    def total(*prices):                 # *args → any number of positional values (a tuple)
    return sum(prices)
total(10, 20, 30)                   # → 60

def profile(**info):                # **kwargs → any number of named values (a dict)
    return info
profile(name="Asha", city="Pune")   # → {'name': 'Asha', 'city': 'Pune'}

def connect(host, *, timeout=30):   # everything after * must be passed by name
    ...
connect("db", timeout=5)            # ✅
connect("db", 5)                    # ❌ TypeError

    Closures: functions that remember

    def make_multiplier(n):
    def multiply(x):
        return x * n        # n is remembered from the outer function
    return multiply

double = make_multiplier(2)
triple = make_multiplier(3)
print(double(5), triple(5))  # → 10 15
    🤔 Predict the output
    x = "global"

def show():
    x = "local"
    print(x)

show()
print(x)
    Show answer 
    local
global

    The x inside show is a separate local name. The global x is untouched.

    ✅ Remember
    • Functions are objects — you can pass them around (key=, callbacks).
    • Names are looked up Local → Enclosing → Global → Built-in.
    • Prefer returning values over changing globals.
    • Never use [] or {} as a default — use None.
    🔬 Go deeper — nonlocal, late binding, argument rules

    global and nonlocal

    def make_counter():
    count = 0
    def increment():
        nonlocal count      # rebind the enclosing function's variable
        count += 1
        return count
    return increment

c = make_counter()
c(); c()                    # → 1, then 2

    global name does the same for a module-level variable. Both are rarely needed — returning values is usually clearer.

    Late binding in closures

    funcs = [lambda: i for i in range(3)]
[f() for f in funcs]        # → [2, 2, 2]   all read i when CALLED

funcs = [lambda i=i: i for i in range(3)]
[f() for f in funcs]        # → [0, 1, 2]   default arg freezes each value

    Closures remember the variable, not the value it had at the time.

    Full parameter order

    def f(pos_only, /, normal, *args, kw_only, **kwargs): ...

    Before /: positional only. After *: keyword only.

    Functions carry metadata

    f.__name__, f.__doc__, f.__defaults__ (you can literally see the shared default list there), f.__closure__.

    ⚠️ Common mistakes

    The traps that catch almost everyone at least once.

    1. Using is to compare values — use == (and is only for None).
    2. Thinking b = a copies a list — it doesn't; use .copy().
    3. Using .copy() on nested data and expecting the inner lists to be separate — use deepcopy.
    4. Using a list as a dict key — use a tuple.
    5. Deleting dict keys while looping over the dict — loop over list(d).
    6. Checking x in big_list over and over — convert to a set once.
    7. "Age: " + 25 — use an f-string.
    8. Building long strings with += in a loop — use "".join().
    9. Opening files without encoding="utf-8".
    10. Modifying a global inside a function → UnboundLocalError. Return a value instead.
    11. def f(items=[]) — the default is shared between calls. Use None.
