    MODULE 1

    The Python Object Model

    🔑 Core idea

    Everything in Python is an object — integers, strings, functions, classes, modules, even None. Every object has exactly three things:

    PropertyWhat it isCan it change?Inspect with
    IdentityUnique id (memory address in CPython)Neverid(x)
    TypeWhat kind of object it isNevertype(x)
    ValueThe data it holdsOnly if mutableprint(x)
    🧠 Memory trick

    Every object watches “ITV”: Identity · Type · Value.

    The first two are fixed at birth. Only the value of a mutable object can change.

    is vs ==

    OperatorAsksUnder the hood
    isSame object? (identity)id(a) == id(b)
    ==Same value? (equality)a.__eq__(b)
    a = [1, 2, 3]
b = [1, 2, 3]
c = a

a == b    # True  — same contents
a is b    # False — two different list objects
a is c    # True  — c is just another name for a

x = None
if x is None:      # ✅ the idiomatic None check
    print("nothing here")
    🧠 Memory trick

    is = “is it the same box?” · == = “same contents?”

    Use is only for singletons: None, True, False.

    Mutable vs immutable

    🔓 Mutable — can change in place

    listdictsetbytearraymost custom objects

    🔒 Immutable — can never change

    intfloatboolstrtuplefrozensetbytesNone
    ConsequenceMutableImmutable
    Dict key / set member❌ Unhashable✅ Hashable
    Shared between threads⚠️ Needs locks✅ Safe
    As a default argument⚠️ Shared-state trap✅ Safe
    🧠 Memory trick

    “Lists, Dicts, Sets Live Dangerously Sometimes.”

    The three everyday containers with curly/square brackets are mutable. Everything “simple” (numbers, strings, tuples) is frozen.

    Mental model: sticky labels

    Variables are sticky labels on boxes in a warehouse. x = 42 sticks the label x on the box containing 42. y = x puts a second label on the same box — nothing is copied.

    a = [1, 2, 3]
b = a            # second label on the same list
b.append(4)
print(a)         # [1, 2, 3, 4] — a sees the change
print(a is b)    # True
    ⚠️ Don't forget
    • type(type) → <class 'type'> — type is an instance of itself.
    • None is a singleton — there is exactly one in the whole process.
    • Immutable ≠ constant: you can rebind the name, you just can't change the object.
    • CPython caches small ints [-5, 256], so a is b may “work” for small numbers. It's an implementation detail — never rely on it.
    • A tuple holding a mutable is still unhashable: {(1, [2]): "v"} → TypeError.
    🤔 Predict the output
    t = (1, [2, 3])
print(type(type))
print(t[1] is t[1])
print(hash(t))
    Show answer 
    <class 'type'>
True
TypeError: unhashable type: 'list'

    A tuple is only hashable if everything inside it is hashable — the list inside poisons it.

    MODULE 2

    Variables & Memory

    🔑 Core idea

    Variables are name bindings (labels), not containers. = never copies — it only moves a label. CPython frees an object when its reference count drops to zero.

    Reference counting

    import sys

x = "hello world"   # refcount = 1
y = x               # refcount = 2  (two labels)
del x               # refcount = 1  (del removes the NAME, not the object)
y = None            # refcount = 0  → object is destroyed

# sys.getrefcount(obj) always reports +1:
# passing obj into the function creates a temporary reference.

    What CPython caches (interning)

    CachedRangeWhy
    Small integers-5 … 256Extremely common values
    StringsIdentifier-like ("name", "id")Fast attribute / dict lookups
    SingletonsNone, True, FalseOnly one instance ever

    Shallow vs deep copy

    MethodWhat it copiesUse for
    b = aNothing — new label onlyIntentionally shared state
    copy.copy(a) / a.copy() / a[:]The outer container onlyFlat structures
    copy.deepcopy(a)Everything, recursivelyNested structures you must isolate
    SHALLOW COPY                              DEEP COPY
original ──► {"users": ─┐                 original ──► {"users": ──► [A, B]}
                        ├──► [A, B]
shallow  ──► {"users": ─┘                 deep     ──► {"users": ──► [A', B']}
(new dict, SAME inner list)               (new dict, NEW list, NEW inner dicts)
    import copy

original = {"users": [{"name": "Alice"}]}
shallow  = copy.copy(original)
deep     = copy.deepcopy(original)

shallow["users"].append({"name": "Bob"})
print(len(original["users"]))   # 2  ← original mutated through the shallow copy!

deep["users"].append({"name": "Charlie"})
print(len(original["users"]))   # 2  ← deep copy is fully independent
    🧠 Memory trick — the photocopier

    = is writing a second name on the same notebook. copy() photocopies only the cover page (the inner pages are still shared). deepcopy() photocopies every page.

    Passing arguments: by object reference

    Python is neither pass-by-value nor pass-by-reference. The function gets a new label on the same object.

    def modify(lst):
    lst.append(4)        # mutates the shared object → caller sees it ✅

def rebind(lst):
    lst = [9, 9, 9]      # moves the LOCAL label only → caller unaffected ❌

a = [1, 2, 3]
modify(a);  print(a)     # [1, 2, 3, 4]
rebind(a);  print(a)     # [1, 2, 3, 4]  (unchanged)
    🧠 Memory trick

    “Mutations travel, rebinds stay home.”

    Changing the object inside a function is visible outside. Pointing the parameter at a new object is not.

    ⚠️ Don't forget
    • += on a mutable mutates in place; on an immutable it creates a new object and rebinds.
    • del x deletes the name. The object dies only when nothing else refers to it.
    • Use copy.deepcopy() for nested structures you need to isolate.
    🤔 Predict the output
    a = [1, 2]
b = a
a += [3]          # list +=
print(b)

s = "hi"
t = s
s += "!"          # str +=
print(t)
    Show answer 
    [1, 2, 3]
hi

    List += calls __iadd__ and mutates the shared list. Strings are immutable, so s += "!" builds a new string and moves only the label s.

    MODULE 3

    Data Structures Deep Dive

    🔑 Core idea

    Python's four core containers are backed by specific C implementations — and that dictates their speed. Pick the structure by the operation you do most.

    list — a dynamic array of pointers

    OperationTimeWhy
    lst[i]O(1)Direct offset
    lst.append(x)O(1) amortizedOver-allocates spare capacity
    lst.pop()O(1)Removes from the end
    lst.insert(0, x)O(n)Shifts every element right
    lst.pop(0)O(n)Shifts every element left — use deque
    x in lstO(n)Linear scan

    dict — a compact hash table

    OperationAverageNotes
    d[key], d[key] = vO(1)Resizes at ~⅔ full
    key in dO(1)Hash, then compare
    Iteration order—Insertion order — a language guarantee since 3.7

    set and tuple

    • set = hash table of keys only → O(1) membership. Operators: a | b union, a & b intersection, a - b difference, a ^ b symmetric difference.
    • tuple = fixed-size immutable array → smaller than a list, and hashable (if its contents are) so it can be a dict key.
    list : [ptr0|ptr1|ptr2|...|empty|empty]   ← over-allocated, room to grow
tuple: [ptr0|ptr1|ptr2]                   ← exact size, no growth buffer
dict : indices[sparse] → entries[dense, insertion order]
set  : hash table of keys only (no values)
    🧠 Memory trick — choose by question
    • “Is X in here?” (asked many times) → set
    • “What's the value for X?” → dict
    • “Add/remove at both ends?” (queue) → deque
    • “Ordered, indexable, grows at the end?” → list
    • “Fixed record / dict key?” → tuple

    The collections trio

    from collections import defaultdict, Counter, deque

# defaultdict — auto-creates missing keys
d = defaultdict(list)
d["users"].append("Alice")
print(d["admins"])            # []  ← reading CREATED the "admins" key!

# Counter — frequency counting in one line
words = ["the", "cat", "the", "dog", "the"]
Counter(words).most_common(2) # [('the', 3), ('cat', 1)]

# deque — O(1) at both ends
q = deque([1, 2, 3])
q.appendleft(0)               # O(1)  (list.insert(0, x) is O(n))
q.popleft()                   # O(1)  (list.pop(0) is O(n))
    ⚠️ Don't forget
    • Defining __eq__ without __hash__ makes a class unhashable.
    • Insertion order ≠ sorted order.
    • Never add/remove keys of a dict or set while iterating it → RuntimeError. Iterate over list(d) instead.
    • defaultdict inserts on read. Use d.get(key) if you only want to peek.
    • Checking in repeatedly against a list? Convert it to a set once.
    🤔 Predict the output
    d = {"a": 1, "b": 2}
for k in d:
    if k == "a":
        d["c"] = 3
    Show answer 
    RuntimeError: dictionary changed size during iteration

    Fix: for k in list(d): — iterate over a snapshot of the keys.

    MODULE 4

    Strings & Unicode

    🔑 Core idea

    str = a sequence of Unicode characters (text). bytes = a sequence of raw bytes (what goes over the wire and onto disk). Decode at the boundary, work with str inside, encode at the boundary.

    bytes in
    file · network     → .decode("utf-8") → str
    your program     → .encode("utf-8") → bytes out
    file · network
    🧠 Memory trick — the Unicode sandwich

    Bread = bytes, filling = str.

    Decode when data comes in (“De-in”), Encode when it goes out (“En-out”). Never mix the two inside.

    UTF-8 is variable-width

    Code point rangeBytesExample
    U+0000 – U+007F1A
    U+0080 – U+07FF2é
    U+0800 – U+FFFF3世
    U+10000 – U+10FFFF4🐍
    len("🐍")                     # 1  → characters
len("🐍".encode("utf-8"))     # 4  → bytes

"café".encode("utf-8")        # b'caf\xc3\xa9'
b"caf\xc3\xa9".decode("utf-8")  # 'café'

"a" + b"b"                    # TypeError — str and bytes never mix implicitly

    PEP 393 (internal storage): CPython stores each string using the smallest width that fits all its characters (1, 2 or 4 bytes per char). One emoji in a million-character ASCII string makes the whole string ~4× bigger in memory.

    Fast concatenation & f-strings

    # ❌ O(n²): each += builds a brand-new string
result = ""
for item in items:
    result += str(item) + ", "

# ✅ O(n): collect, then join once
result = ", ".join(str(item) for item in items)

# Always state the encoding when opening text files
with open("data.csv", "r", encoding="utf-8") as f:
    data = f.read()

# f-string mini-language
name, pi = "Alice", 3.14159
f"{pi:.2f}"        # '3.14'
f"{1000000:,}"     # '1,000,000'
f"{name=}"         # "name='Alice'"   (3.8+ debug form)
f"{name:>8}"       # '   Alice'       (right-align in 8 chars)
    🧠 Memory trick

    “+= in a loop is a re-write; join is a one-shot print.”

    ⚠️ Don't forget
    • len(str) counts characters; len(bytes) counts bytes — different for non-ASCII.
    • Always pass encoding="utf-8" to open() — the default depends on the OS (it bites on Windows).
    • Decode network input explicitly as UTF-8.
    MODULE 5

    Functions & Scoping

    🔑 Core idea

    Functions are first-class objects — you can assign, pass, return and store them. Names are resolved with the LEGB rule: Local → Enclosing → Global → Built-in.

    The LEGB scope chain

    B · Built-in — len, print, range
    G · Global — module-level names
    E · Enclosing — outer function's locals
    L · Local — names assigned inside this function (searched first)
    🧠 Memory trick

    “Look Everywhere, Going Bigger.”

    Python starts in the smallest box (Local) and walks outward until it finds the name — or raises NameError.

    x = "global"

def outer():
    x = "enclosing"
    def inner():
        x = "local"
        print(x)     # local  — L wins
    inner()

outer()
print(len)           # <built-in function len> — found in B

    global vs nonlocal

    KeywordRebinds a name in…Typical use
    globalThe module scopeRare — module-level config
    nonlocalThe nearest enclosing functionClosures: counters, accumulators
    (neither)Creates a new localDefault behaviour
    def make_counter():
    count = 0
    def increment():
        nonlocal count      # without this → UnboundLocalError
        count += 1
        return count
    return increment

c = make_counter()
c()   # 1
c()   # 2   ← count survives between calls: that's a closure

    The UnboundLocalError trap

    x = 10
def f():
    print(x)    # UnboundLocalError!
    x = 20      # this assignment makes x local for the WHOLE function
    🧠 Memory trick

    “Assign anywhere → local everywhere.”

    Python decides scope at compile time by scanning the whole function body.

    Default arguments are evaluated once

    def bad(items=[]):          # ONE list, created at def time
    items.append(1)
    return items

bad()   # [1]
bad()   # [1, 1]   ← same list reused!

def good(items=None):       # ✅ None sentinel
    if items is None:
        items = []
    items.append(1)
    return items
    🧠 Memory trick

    “Defaults are baked once, not per call.”

    Same trap for timestamps: def log(ts=datetime.now()) freezes the time of definition.

    Closures & late binding

    Closures capture variables, not values. The value is looked up when the inner function runs.

    funcs = [lambda: i for i in range(5)]
[f() for f in funcs]        # [4, 4, 4, 4, 4]  ← all see the final i

funcs = [lambda i=i: i for i in range(5)]
[f() for f in funcs]        # [0, 1, 2, 3, 4]  ← default arg freezes the value
    🧠 Memory trick

    “Closures remember the name, not the number — freeze it with i=i.”

    Parameter order

    def f(pos_only, /, normal, *args, kw_only, **kwargs): ...

def connect(host, port, *, timeout=30, retries=3):
    ...

connect("db", 5432, timeout=10)   # ✅
connect("db", 5432, 10)           # ❌ TypeError — timeout is keyword-only
    🧠 Memory trick

    “Slash shields the left, star stars the right.”

    Everything before / is positional-only. Everything after * must be passed by keyword.

    ⚠️ Don't forget
    • Functions are objects with attributes: __name__, __doc__, __defaults__, __closure__, __code__.
    • A lambda is a single expression — no statements, no assignments.
    🤔 Predict the output
    def append_to(x, bucket=[]):
    bucket.append(x)
    return bucket

print(append_to(1))
print(append_to(2))
print(append_to.__defaults__)
    Show answer 
    [1]
[1, 2]
([1, 2],)

    You can literally see the shared list living on the function object in __defaults__.

    ⚠️ Gotchas checklist

    Skim this the night before an interview.

    1. is for value comparison → wrong. Only for None, True, False.
    2. Integer cache [-5, 256] is CPython-specific — never rely on it.
    3. def f(x=[]) → shared across calls. Use a None sentinel.
    4. += on a list mutates in place; on a tuple/str it creates a new object.
    5. Shallow copy shares inner objects → deepcopy for nested data.
    6. del deletes the name, not the object.
    7. Pass-by-object-reference ≠ pass-by-reference — the rebind test proves it.
    8. list.insert(0) / list.pop(0) are O(n) → use deque.
    9. Defining __eq__ without __hash__ → unhashable class.
    10. Mutating a dict/set while iterating it → RuntimeError.
    11. defaultdict inserts on read — silent memory growth.
    12. UnboundLocalError: assignment anywhere makes a name local everywhere in that function.
    13. Late-binding closures → fix with lambda i=i: i.
    14. String += in a loop → O(n²); use join().
    15. len(str) = characters, len(bytes) = bytes.
    16. The tuple += puzzle: t = ([1, 2],); t[0] += [3, 4] raises TypeError — but the list is mutated anyway. Step 1 (list.__iadd__) succeeds; step 2 (assigning back into the tuple) fails.
